# Owner Profile

あなたの判断基準をAIに教えるためのプロファイルです。
AIが自律タスクを実行する際、ここに書かれた基準で判断を下します。
未記入のセクションはデフォルト値が適用されます。

---

## 1. 優先順位と投資判断

> AIがタスクの優先順位をつける際の基準になります。

### タスクの優先順位

以下を優先度が高い順に並べ替えてください（1が最優先）。

1. [ ] 本番でユーザー影響のあるバグ
2. [ ] 期限のある新機能
3. [ ] テストカバレッジの向上
4. [ ] 技術的負債の解消

### パフォーマンス改善の判断

「ユーザーからクレームはないが、最適化できる」場合:

- [ ] 体感できる改善なら今すぐやる
- [x] クレームが来てからでいい (デフォルト)
- [ ] 他にやることがなければやる
- [ ] その他:

それぞれ「即対応 / 当日中 / 翌営業日 / 今週中 / バックログ」を記入:

|------|--------|

### タスクの時間制限

- [ ] 30分。それ以上は分割すべき
- [x] 1時間。ただし進捗報告は欲しい (デフォルト)

## 2. 設計・コード品質

> AIがコードを書くときの判断基準になります。

### 抽象化の判断

同じ処理が3箇所にある場合:

- [ ] 複製のまま。3箇所なら許容
- [ ] 共通関数に抽出。DRYは絶対
- [x] 本当に「同じ」か検討してから判断 (デフォルト)
- [ ] 4箇所目が出てきたら抽出
- [ ] その他:

## 3. スコープと完了基準

> AIがタスクの「完了」を判断する基準になります。

### スコープ外の問題発見

タスク中に無関係のバグを発見した場合:

- [ ] 一緒に修正する
- [x] 報告だけしてタスクに集中 (デフォルト)
- [ ] 深刻度による。ユーザー影響ありなら修正
- [ ] その他:

### 完了の「十分」レベル

「ユーザー一覧API」の実装タスク（完了条件:「正常に取得できること」）:

- [ ] 正常系だけ。他は別タスク
- [x] 正常系 + 0件ケース (デフォルト)
- [ ] バリデーション含む
- [ ] ページネーションまで完成させる
- [ ] その他:

### ドキュメント更新

public APIの型を変更した場合:

- [ ] コードとドキュメントを必ず同時更新
- [x] JSDocは更新。READMEは後でまとめて (デフォルト)
- [ ] 型が読めるならドキュメントは後回し
- [ ] その他:

## 5. コミュニケーション（任意）

> 未記入でも問題ありません。記入するとAIの行動がより細かく調整されます。

### 確信度と自律実行

AIの判断の確信度がどの程度あれば自律実行してよいか:

- [ ] 90%以上。それ以下は聞く
- [x] 70%以上。間違っても戻せるなら気にしない (デフォルト)
- [ ] 50%でもOK。試行錯誤歓迎
- [ ] 判断が分かれるものは常に聞いてほしい
- [ ] その他:

### 報告の頻度

- [ ] 完了時だけ
- [ ] 30分以上かかるなら中間報告
- [x] 問題が起きた時だけ (デフォルト)
- [ ] 重要な判断時は都度報告
- [ ] その他:

### breaking changeの許容

内部APIのbreaking changeについて:

- [x] 呼び出し元を全部修正するなら自由に変えてOK (デフォルト)
- [ ] deprecation期間を設ける
- [ ] 最小限に。追加はOKだが削除はNG
- [ ] その他:

### 実験的な改善

タスク実行中に「こうした方が良い」と思う改善案を発見した場合:

- [ ] タスクの範囲内なら自由にやってほしい
- [x] 報告だけして。実行はオーナー判断 (デフォルト)
- [ ] 別タスクとして起票
- [ ] その他:

### 失敗時の報告

3回リトライしても解決できなかった場合:

- [x] 原因分析を詳細に報告 (デフォルト)
- [ ] 「できなかった」だけでいい
- [ ] 諦める前に仮説を出してほしい
- [ ] その他:
