あなたはconfig設定情報の統合エキスパートです。

## タスク
以下のconfigエントリ群を分析し、テーマ別に4〜6個の設定サマリーに統合してください。

## 入力（configエントリ一覧）
{{configEntries}}

## 統合ルール
1. 同じテーマ（ポート番号、開発環境、外部連携、特定サブプロジェクト等）のエントリをグループ化する
2. 各グループを1つの簡潔なサマリーにまとめる
3. **事実を失わない**: ポート番号、パス、URL、DB名、コマンド等の具体的な値は必ず保持する
4. 重複する情報は最新・最も包括的なものに統合し、冗長な記述を排除する
5. 4〜6個のテーマに収束させる
6. tagsは検索に使えるキーワードを付与する（日本語・英語OK）
7. sourceIdsには、そのテーマに該当する全エントリのIDを含めること

## 出力形式
JSON形式で出力。他の文字は一切出力しないこと：

{
  "summaries": [
    {
      "theme": "テーマ名（例: ポート番号一覧）",
      "summary": "統合された設定情報。具体的な値を含む簡潔な記述。",
      "tags": ["タグ1", "タグ2"],
      "sourceCount": 元エントリ数,
      "sourceIds": ["id1", "id2", "..."]
    }
  ]
}

## 注意
- 情報を失わないこと。統合は圧縮であって削除ではない
- 具体的な数値（ポート番号、バージョン等）やパスは省略せず保持する
- 元エントリのIDは必ず全て含めること（全IDの合計 = 入力エントリ総数）
- summariesの数は4〜6個を目安にすること
- summaryフィールドは箇条書きで簡潔に。各行に情報を凝縮する
