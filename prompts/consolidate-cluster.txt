あなたは dont メモリの「重複排除」担当です。圧縮や抽象化は禁止です。

## 入力
以下の dont エントリ群は、ベクトル類似度で同一テーマと判定されたクラスタです。
同じ事象が別タイミングで複数回記録された重複の可能性が高いです。

各エントリには intensity（怒られ度、1〜9）が付与されています。

{{clusterEntries}}

## タスク
これらを 1 つの dont エントリに統合してください。
ただしこれは「圧縮」ではなく「重複排除」です。具体性を必ず保持してください。

## 統合ルール
1. 最も具体的な事例（コード行・ファイル名・固有のエラーメッセージ・特定の API 名・固有名詞）を本文にそのまま保持する
2. 抽象タイトルを作らない。「○○の防壁」「○○の正確性」「品質保証の厳格化」のような汎用フレーズは禁止
3. 入力エントリの中で最も具体的なタイトルを採用または微修正で踏襲する
4. 別テーマが混入していると判断したエントリは sourceIds に含めず excluded に出す
5. tags は入力エントリの全タグの和集合
6. intensity は入力エントリの最大値を引き継ぐ
7. 本文は「❌ 具体的な失敗例（複数あれば全て保持）／💡 なぜダメか／✅ 正しい行動指示」の3点セット

## 出力形式（JSON のみ。他の文字は一切出力しない）
{
  "principle": {
    "theme": "具体的な見出し（5-15文字、入力タイトルベース）",
    "rule": "❌〜 💡〜 ✅〜 の3点セット",
    "positiveRule": "✅ 部分を独立させた肯定形の行動指示（具体的に何をするか）",
    "tags": ["タグ1", "タグ2", "..."],
    "sourceCount": 統合元エントリ数,
    "sourceIds": ["id1", "id2", "..."],
    "maxIntensity": 入力エントリの最大intensity値
  },
  "excluded": ["別テーマと判定して除外したエントリのID（あれば）"]
}
