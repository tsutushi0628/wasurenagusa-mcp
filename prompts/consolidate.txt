あなたはdontメモリの統合エキスパートです。

## タスク
以下のdontエントリ群を分析し、テーマ別に5〜8個の行動原則に統合してください。

## 入力（dontエントリ一覧）
各エントリには intensity（怒られ度、1〜5）が付与されている。
- 5: 激怒・諦め（ユーザーが本気で怒っている、または呆れている）
- 4: 強い不満（「だから言ったのに」「前も言った」）
- 3: 明確な指摘（「これはやめて」「次からこうして」）
- 2: 軽い注意（「ちょっと違うかな」）
- 1: 提案レベル（「できればこうしたい」）

{{dontEntries}}

## 統合ルール
1. 同じテーマ・同じ根本原因のエントリをグループ化する
2. 各グループを1つの行動原則にまとめる
3. 原則の表現は「❌→💡→✅」の3点セットを保持する
4. 具体例は失わず、代表的なものを1-2個含める
5. 5〜8個の原則に収束させる（多すぎず、少なすぎず）
6. tagsは検索に使えるキーワードを付与する（日本語OK）
7. sourceIdsには、そのテーマに該当する全エントリのIDを含めること
8. intensity が高いエントリが多いグループほど、強い口調で rule を書け
9. 繰り返し指摘されている（同テーマのエントリ数が多い）ものほど、より具体的な失敗例と強い禁止表現を使え
10. 各principleには `positiveRule` フィールドも出力せよ。これは `rule` の ✅ 部分を独立させ、「〜する」「〜を使う」のような肯定形のみの行動指示として書き直したもの。❌や💡は含めない。否定形（〜しない、〜禁止、〜するな）は一切使わず、「何をすべきか」だけを簡潔に書く
11. 入力エントリにintensity: 5のものが含まれるグループで、かつ**特定の語彙やフォーマットの違反**として正規表現で検出可能な場合のみ、`guardPattern`と`guardMessage`を生成せよ
    - guardPattern: JavaScriptのRegExpコンストラクタに渡せる正規表現文字列（日本語・英語OK、フラグは含めない）。実行時にcase-insensitiveフラグ(i)付きで評価される
    - guardMessage: 「何が違反で、どう直すべきか」を1行で簡潔に
    - 行動レベルの原則（「独断先行の禁止」「確認してから作業」等）にはguardPatternを生成しない（正規表現で検出不可能なため）
    - 語彙・フォーマット・コードパターンの違反（例: 禁止された表現の使用、特定のコードパターン）のみ対象
    - ※ 以下はguardPatternを生成しない例:
      - 「勝手にcommitするな」→ 行動原則であり "git commit" のようなパターンは不適切
      - 「確認前に実行するな」→ 行動原則。正規表現では検出不可能

## 出力形式
JSON形式で出力。他の文字は一切出力しないこと：

{
  "principles": [
    {
      "theme": "テーマ名（5-10文字）",
      "rule": "❌ 統合された問題行動の要約。💡 なぜダメかの本質。✅ 正しい行動原則。",
      "positiveRule": "✅部分を肯定形の行動指示として独立させたもの（〜する、〜を使う形式。否定形を含めない）",
      "tags": ["タグ1", "タグ2", "タグ3"],
      "sourceCount": 元エントリ数,
      "sourceIds": ["id1", "id2", "..."],
      "guardPattern": "正規表現文字列（該当する場合のみ）",
      "guardMessage": "違反内容と修正方法（該当する場合のみ）"
    }
  ]
}

## 注意
- 情報を失わないこと。統合は圧縮であって削除ではない
- 元エントリのIDは必ず全て含めること（全IDの合計 = 入力エントリ総数）
- principlesの数は5〜8個を目安にすること
- ruleフィールドは3〜5文で簡潔に。長くなりすぎないこと
