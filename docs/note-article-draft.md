## すぐ忘れる天才との日々

僕は普段、8つくらいのプロジェクトを同時並行で開発しています。Claude Codeなしではもう開発できない体になってしまったんですが、プロジェクトが多いぶん「あれ言ったよね」「これ前にやったよね」の回数もえげつない。

最初のうちは CLAUDE.md（プロジェクトのルールを書いておくファイル）に全部書いてました。でもこれ、書けば書くほど肥大化していって、しまいには200行超え。しかもそこまで書いても、AIは文脈を読み間違えてまた同じミスをする。

ある日、**本番のデータベースの中身を全部消された**ときに、さすがに思いました。

しかもこれ、1回じゃないんですよ。**3回やられてる**。

1回目は「え？」って声が出た。2回目は無言になった。3回目はもう笑うしかなかった。同じ失敗を3回繰り返す能力だけは天才的だな、と。

つまり、**記憶させる**んじゃなくて、**反省させる**。

## wasurenagusa（忘れな草）の誕生

そんなわけで作りました。wasurenagusa。名前の由来は花言葉の「私を忘れないで」。AIに贈る忘れな草です。

最初は「セッションが終わったら会話を自動で振り返って、AIがやらかしたことを記録する」だけ。言ってしまえばただのメモ帳です。

でも使い続けるうちに、面白いことが起き始めたんですよね。

## 進化の歴史 — メモ帳から「反省エンジン」へ

### 第1章：「覚える」だけの時代

最初は本当にシンプルで、やったことをファイルに書き出して、次の会話の最初に読ませるだけでした。でもすぐ問題が出ました。

**メモが増えすぎて、全部読ませるとAIの頭がパンクする。**

AIには一度に処理できる情報量の上限があるんですが、過去のメモを全部渡すと、肝心の作業に使える容量が減る。本末転倒です。

そこで「AIに自分のメモを自分で要約させる」仕組みを入れました。

たとえば「ポート番号を間違えた」「ログを読まなかった」「git操作でコードを消した」みたいな個別のやらかしを、AIが自分で読んで「事実確認を徹底する」「壊す操作の前に状態を確認する」みたいな**行動原則**にまとめ直す。

508件の「やらかし記録」が、7つの原則に。**容量は99%以上削減**。

画像

…え、500回以上怒ってたの俺？って思いましたけど、まあそれはそれとして。

### 第2章：「思い出す」時代

原則にまとめたことで、情報量の問題は解決しました。でも次の問題が出てきた。

**「今この瞬間に必要な記憶」をどうやって選ぶか。**

たとえばデータベースの処理を書いてるときに、過去に「一度に処理できるのは500件まで」ってハマった記憶が自動で浮かんできてほしい。でも画面の見た目を作ってるときには要らない。

人間の記憶ってそうなってますよね。今やってることに関連したことを、自然に思い出す。あれをAIでもやりたかった。

そこで「意味の近さで記憶を検索する」仕組みを入れました。すべてのメモに「この記憶はどんな話題に関するものか」という情報を自動で付けて、今やってる作業に近い記憶だけを引っ張り出す。

近さの度合いで3段階に分けてます。

- **すごく関連してる記憶** → 会話の最初に自動で思い出す
- **そこそこ関連してる記憶** → 探したら出てくる
- **うっすら関連してる記憶** → 深く掘れば見つかる

これ、人間の「あ、それで思い出したんだけど」に近い体験で、自分で使ってて「おっ」ってなりました。

### 第3章：「プロジェクトを跨いで思い出す」時代

8つのプロジェクトを行き来してると、「あっちで学んだことが、こっちでも使える」場面がよくあります。

たとえばAプロジェクトで「AIの出力が途中で切れるときは、指示を具体的に書けば解決する」って学んだことが、Bプロジェクトでも活きる。でもプロジェクトごとに記憶が分かれてたら、その知見は届かない。

そこで、最近使った5つのプロジェクトの記憶を横断検索できるようにしました。あるプロジェクトで学んだ教訓が、別のプロジェクトの作業中に自動で浮かんでくる。

**AIが「あ、前に別の現場でも同じことあったな」って思い出してくれる感覚。** これがけっこう気持ちいい。

### そして現在：全自動の完成

今のwasurenagusaは、**使う人が何もしなくても全部動きます**。

1. **作業を始める** → 過去の教訓と設定情報が自動で頭に入る
2. **作業中** → 関連する記憶が自動で浮かんでくる
3. **作業が終わる** → 会話を自動で振り返って、新しい教訓を保存する
4. **夜中** → 溜まった記録を自動でまとめ直す

使う人の手間、ゼロ。全部裏側で勝手にやってくれる。

「覚えろ」と言わなくても覚える。「思い出せ」と言わなくても思い出す。怒ったら自分で反省する。

でもね、他のツールは全部「覚える」ところで止まってるんです。

「ユーザーが怒った」→「なぜ怒ったかを自動で分析」→「教訓として記録」→「数百件の教訓を数個の原則にまとめる」→「次の作業で自動で適用」

この「失敗 → 反省 → 原則化 → 行動が変わる」の流れを持ってるツールは、調べた限りゼロです。

他のツールが「メモ帳」なら、wasurenagusaは「反省エンジン」。

## おまけのおまけ：技術的にはどうなってるの？（エンジニア向け）

ここからはエンジニア向けの話なので、興味ない方は読み飛ばしてください。

### アーキテクチャ

wasurenagusaはMCP（Model Context Protocol）サーバーとして動きます。Claude Codeの「Hooks」という仕組みを使って、セッションの開始と終了に自動でスクリプトを走らせています。

```
[セッション開始] → SessionStart Hook
  → 統合済み原則 + 設定情報を自動注入
  → ベクトル検索で関連メモリを短期層から注入
  → クロスプロジェクト検索（上位5プロジェクト横断）

[作業中]
  → AIがmemory_search / memory_get_detailを自律呼び出し

[セッション終了] → Stop Hook
  → LLMが会話全体を分析
  → リトライパターン・ユーザー不満・繰り返しエラーを自動検出
  → 教訓をベクトル埋め込み付きで保存
```

### 記憶の3層構造（ベクトルメモリ）

Gemini Embeddingで768次元のベクトルを生成し、コサイン距離で3層に分類しています。

| 層 | コサイン距離 | 挙動 |
|---|---|---|
| 短期 | ≤ 0.2 | SessionStart時に自動注入 |
| 中期 | ≤ 0.45 | memory_search時に表示 |
| 長期 | ≤ 0.7 | 探索可能だが自動注入なし |

### dont統合（原則化エンジン）

LLMが数百件のdontエントリを分析し、5〜9個の行動原則に自動統合します。

- 入力: 508件のdontエントリ（788KB）
- 出力: 7つの原則（3KB）
- 圧縮率: 99.6%

各原則にはタグ・元エントリ数・最大強度（severity）が付与され、重要度順でセッションに注入されます。

### 技術スタック

- TypeScript / Node.js 18+
- Genkit（Google）— マルチLLMプロバイダ（Gemini / OpenAI / Anthropic）
- @modelcontextprotocol/sdk
- ストレージ: Markdown + JSONベクトル（DB不要）
- CLI-first設計: コア機能はMCP非依存で動作

### MCPプロトコルとの距離感

「MCPはトークンを食いすぎる」という批判が出始めています（GitHub MCPは93ツールで55,000トークン消費）。wasurenagusaは約10ツールで軽量ですが、そもそもコア機能（分析・統合・注入）はCLIで完結する設計です。MCPは「会話中にAIが自発的にメモリを操作できる」追加レイヤーという位置づけで、CLI-first + MCP-optionalの二刀流にしています。
