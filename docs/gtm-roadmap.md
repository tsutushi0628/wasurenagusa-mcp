## 判断事項（Decision Log）

### D1: ターゲットプラットフォーム
- **決定**: Phase 1は Claude Code 特化
- **却下案**: 全ツール同時対応（Cipher方式）
- **根拠**: ドッグフーディングできないツールに対応しても最高の体験は作れない。claude-mem(32.6k)がClaude特化で成功、Cipher(3.6k)が12+ツール対応で伸び悩み。狭く深くが正解
- **将来**: しんたろうさん自身が他ツールを使い始めたら対応を検討

### D2: マネタイズ
- **決定**: Phase 1 OSS無料 → Phase 2 Hosted API（将来）
- **根拠**: コアはOSSで信頼を獲得。「APIキー設定不要」を有料の自然な導線にする

### D3: 会社 vs 個人
- **決定**: 個人プロジェクトとしてリリース
- **根拠**: 弁護士ドットコムのブランド戦略とは独立。法務ゲート不要

### D4: 発信者ポジショニング
- **決定**: エンジニアとしてではなく、「AIとの働き方を考える人」として発信
- **却下案**: Zenn/dev.toでの技術記事主体の発信
- **根拠**: しんたろうさんのブランド方針。技術者は GitHub README で勝手に見つける

## リスクと対策

| リスク | 確率 | ダメージ | 対策 |
|--------|------|---------|------|
| Anthropic純正メモリ強化 | 中 | 致命的 | 「思想の深さ」で差別化。統合プロンプトの質が勝負 |
| 初期トラクション失敗 | 高 | 大 | ドッグフーディング実績を前面に。「メモリ」ではなく「反省」でカテゴリ再定義 |
| メンテ体力 | 高 | 大 | スコープを小さく保つ。コア機能以外は受け付けない |
